## 2. 실행한 명령

```text

rtk kubectl apply --server-side -k apps/docs-site
rtk kubectl rollout status deployment/mini-science-ai-os-ko-site -n science-ai-system --timeout=5m
rtk kubectl get deployment,pod,service,ingress,networkpolicy -n science-ai-system -l app.kubernetes.io/name=mini-science-ai-os-ko-site -o wide
rtk curl -sS -o /dev/null -w 'status=%{http_code} remote=%{remote_ip} bytes=%{size_download}' http://mini-science-ai-os.192.168.0.56.nip.io/
```

## 4. 발견한 문제와 위험

- 첫 렌더링에서 `/favicon.ico` 404가 발생했다. inline SVG data favicon을 추가한 뒤 Browser Console 오류는 0건이다.
- Ingress는 현재 HTTP이며 TLS를 구성하지 않았다.
- `nip.io` DNS에 접근할 수 없는 환경에서는 Port Forward가 필요하다.
- Google Fonts가 차단되면 시스템 한글 Font fallback으로 표시된다. 페이지 기능에는 영향이 없다.
- NetworkPolicy Manifest는 배포했지만 현재 Flannel-only CNI에서 enforcement는 여전히 BLOCKED다.
- 첫 번째 배포가 만든 미사용 ConfigMap `mini-science-ai-os-ko-site-bmgb9bd886`은 현재 Deployment에서 참조되지 않는 것을 확인한 뒤 삭제했다. 현재 HTML은 source와 최신 hashed ConfigMap으로 복구 가능하다.

## 5. 다음 단계 진행 가능 여부

페이지 배포와 HTTP·브라우저 검증은 PASS다. 외부 공개 전 TLS와 인증/접근 제한을 추가해야 한다. Argo CD GitOps 동기화는 Repository URL이 없으므로 기존 BLOCKED 상태다.

## 6. 0.0.0.0 Port Forward

사용자 요청에 따라 다음 Port Forward를 추가 실행했다.

```text
rtk kubectl -n science-ai-system port-forward --address=0.0.0.0 service/mini-science-ai-os-ko-site 8088:80
Forwarding from 0.0.0.0:8088 -> 8080
```

실제 확인 결과:

```text
LISTEN 0.0.0.0:8088
http://127.0.0.1:8088/       HTTP 200, 24083 bytes
http://192.168.0.56:8088/    HTTP 200, 24083 bytes
```

이 Port Forward는 현재 실행 Session에 종속된 임시 Process다. 인증과 TLS가 없으므로 신뢰된 내부망 외부로 노출해서는 안 된다.
